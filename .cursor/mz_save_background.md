# RPG Maker MZ Save File Analysis

Below is a practical technical analysis of RPG Maker MZ save files, with emphasis on how they are stored, decoded, edited, and restored.

A key clarification first:

> **RPG Maker MZ save files are normally not `.rmmzdata` files.**  
> The usual save-file extension is:

```text
.rmmzsave
```

Typical examples:

```text
file1.rmmzsave
file2.rmmzsave
global.rmmzsave
config.rmmzsave
```

The extension `.rmmzdata` is sometimes seen in deployed/encrypted game data or third-party tooling contexts, but the standard RPG Maker MZ runtime save files are generally `.rmmzsave`.

---

# 1. Save File Format

## 1.1 Standard RPG Maker MZ Save File Extension

RPG Maker MZ save files are usually stored as:

```text
*.rmmzsave
```

For example:

```text
save/file1.rmmzsave
save/file2.rmmzsave
save/global.rmmzsave
save/config.rmmzsave
```

These files are generated by the RPG Maker MZ runtime through the internal `StorageManager`.

---

## 1.2 Internal Format

A normal RPG Maker MZ save file is:

```text
LZString-compressed Base64 text containing serialized JSON data
```

The rough pipeline is:

```text
Game Object
   ↓
JsonEx.stringify(...)
   ↓
LZString.compressToBase64(...)
   ↓
.rmmzsave file
```

When loading:

```text
.rmmzsave file
   ↓
LZString.decompressFromBase64(...)
   ↓
JsonEx.parse(...)
   ↓
Game Object
```

So the save file is not plain JSON, but it can be decoded into JSON-like structured data.

---

## 1.3 Encoding

RPG Maker MZ uses JavaScript internally. The save data is serialized to a string and then compressed.

The general encoding stack is:

| Layer | Description |
|---|---|
| Game object data | RPG Maker runtime objects such as party, map, actors, switches |
| `JsonEx.stringify` | RPG Maker’s extended JSON serializer |
| `LZString.compressToBase64` | Compresses the JSON string into Base64 text |
| File write | Stored as `.rmmzsave` |

The compressed save file usually appears as a long Base64-like string, for example:

```text
N4Igzg9grgTgxgUxALhA...
```

It is not meant to be edited directly in a text editor.

---

## 1.4 Important Related Files

RPG Maker MZ save systems usually involve several save-related files:

```text
global.rmmzsave
config.rmmzsave
file1.rmmzsave
file2.rmmzsave
...
```

### `global.rmmzsave`

Stores global save metadata, such as:

- Which save slots exist
- Display information for save slots
- Playtime
- Party preview info
- Current map name or location display
- Timestamp

### `config.rmmzsave`

Stores player configuration, such as:

- Volume settings
- Always dash
- Command remember
- Touch UI settings
- Window opacity or related options
- Other plugin-added settings

### `fileN.rmmzsave`

Stores the actual game progress for slot `N`.

Example:

```text
file1.rmmzsave
file2.rmmzsave
file3.rmmzsave
```

# 2. Metadata Information

RPG Maker MZ save data contains both **metadata** and **full game state**.

The exact contents can vary depending on plugins, but standard MZ save files typically include the following.

---

## 2.1 Save Slot Metadata

Save metadata is usually produced by:

```javascript
DataManager.makeSavefileInfo()
```

Typical metadata includes:

| Field | Meaning |
|---|---|
| `title` | Game title |
| `characters` | Character sprites displayed in save menu |
| `faces` | Actor face images displayed in save menu |
| `playtime` | Total playtime |
| `timestamp` | Save creation/update timestamp |
| `mapName` | Current map display name |
| `party` | Basic party preview data |
| `versionId` | Project version identifier |

A simplified example may look like:

````json
{
  "title": "My RPG",
  "characters": [
    ["Actor1", 0],
    ["Actor2", 1]
  ],
  "faces": [
    ["Actor1", 0],
    ["Actor2", 1]
  ],
  "playtime": "12:34:56",
  "timestamp": 1710000000000,
  "mapName": "Forest Village"
}
````

---

## 2.2 Main Game Progress Data

The actual save slot file contains the full runtime state.

Internally, RPG Maker MZ saves data similar to this:

````json
{
  "system": "...",
  "screen": "...",
  "timer": "...",
  "switches": "...",
  "variables": "...",
  "selfSwitches": "...",
  "actors": "...",
  "party": "...",
  "map": "...",
  "player": "..."
}
````

The important categories are:

---

## 2.3 Player and Map State

Usually includes:

- Current map ID
- Player X/Y coordinates
- Player direction
- Vehicle state
- Followers
- Encounter count
- Current transfer state
- Event positions and states on the current map

Common fields are conceptually related to:

```javascript
$gameMap
$gamePlayer
$gameVehicle
$gameFollowers
```

---

## 2.4 Actors and Party

Actor and party data includes:

- Party members
- Actor levels
- Actor HP/MP/TP
- Experience
- Skills
- Equipment
- States/status effects
- Class information
- Formation order

Related runtime objects:

```javascript
$gameActors
$gameParty
```

---

## 2.5 Items, Weapons, Armors, and Gold

The save file stores inventory-related data, including:

- Items
- Weapons
- Armors
- Gold
- Number of each item
- Possibly key items
- Plugin-added inventory extensions

Related runtime object:

```javascript
$gameParty
```

---

## 2.6 Switches and Variables

These are very important in RPG Maker games.

### Switches

Switches are boolean flags:

```text
ON / OFF
```

They control things such as:

- Quest completion
- Door opened/closed
- NPC dialogue progression
- Cutscene completion
- Boss defeated
- Area unlocked

Runtime object:

```javascript
$gameSwitches
```

### Variables

Variables store numeric or other values:

```text
quest_stage = 5
coins_collected = 23
relationship_value = 80
```

Runtime object:

```javascript
$gameVariables
```

---

## 2.7 Self Switches

Self switches are local event flags.

They usually look conceptually like:

```text
[mapId, eventId, switchName]
```

Example:

```text
Map 3, Event 12, Self Switch A = true
```

They control individual event states, such as:

- Chest opened
- NPC event completed
- Door state
- Puzzle object activated

Runtime object:

```javascript
$gameSelfSwitches
```

---

## 2.8 System Settings

Game system data may include:

- Save enabled/disabled
- Menu enabled/disabled
- Encounter enabled/disabled
- Formation enabled/disabled
- Battle count
- Win count
- Escape count
- BGM/BGS memory
- Window tone
- Game timer
- Version ID

Runtime object:

```javascript
$gameSystem
```

---

## 2.9 Plugin Data

Many RPG Maker MZ games use plugins.

Plugins may add custom save data through:

```javascript
DataManager.makeSaveContents
DataManager.extractSaveContents
```

Therefore, save files may contain additional fields such as:

```json
"questSystem": "...",
"achievementData": "...",
"craftingData": "...",
"relationshipData": "...",
"customInventory": "..."
```

Plugin data is one major reason why save files from different games are not always structurally compatible.

# 4. File Creation Process

## 4.1 How Save Files Are Created

During gameplay, save files are created when the game calls:

```javascript
DataManager.saveGame(savefileId)
```

The save process is approximately:

```text
Player opens Save menu
   ↓
Player selects save slot
   ↓
DataManager.saveGame(savefileId)
   ↓
DataManager.makeSaveContents()
   ↓
JsonEx.stringify(...)
   ↓
StorageManager.saveObject(...)
   ↓
LZString.compressToBase64(...)
   ↓
StorageManager.saveZip/saveFile depending on runtime
   ↓
fileN.rmmzsave is written
```

---

## 4.2 Standard Save Trigger

The usual save trigger is:

```text
Menu → Save → Select Slot → Confirm
```

This creates or overwrites:

```text
fileN.rmmzsave
```

For example, saving to slot 1 creates:

```text
save/file1.rmmzsave
```

---

## 4.3 Autosave

RPG Maker MZ supports autosave behavior depending on game configuration and event commands.

Autosave may be triggered by:

- Map transfer
- Battle end
- Custom plugin logic
- Script calls
- Event command
- Developer-defined autosave point

Autosave often uses a special save slot internally, commonly save slot `0` or a designated autosave slot depending on implementation.

---

## 4.4 Event-Based Saving

A game developer can call saving through events or scripts.

For example, a script call may invoke:

```javascript
DataManager.saveGame(1);
```

This saves to slot 1.

A plugin may also expose commands such as:

```text
Auto Save
Save Game
Save To Slot
```

The exact command depends on the plugin.

# 5. Editing Process

This section describes how to decode, inspect, edit, and re-encode RPG Maker MZ save files.

> **Important:** Always create a backup before editing.

```text
file1.rmmzsave → file1_backup.rmmzsave
```

---

# 5.1 Required Tools

You can use several approaches.

## Option A: Node.js

Recommended because RPG Maker MZ itself runs on JavaScript.

Required:

```text
Node.js
npm
lz-string package
A code editor such as VS Code
```

Install dependency:

```bash
npm install lz-string
```

---

## Option B: Browser Console

You can use the browser developer console if the game is running in a browser/NW.js environment and has access to RPG Maker MZ runtime objects.

Useful runtime objects:

```javascript
StorageManager
DataManager
JsonEx
LZString
$gameParty
$gameSwitches
$gameVariables
```

---

## Option C: Existing Save Editors

There are generic RPG Maker save editors online, but compatibility is not guaranteed because:

- MZ save format differs from older RPG Maker formats
- Plugins may add custom data
- Some games encrypt or obfuscate data
- Some games modify save serialization

Use such tools carefully and always back up saves.

---

# 5.2 Decoding a Save File with Node.js

Create a script:

```text
decode-mz-save.js
```

Example:

````javascript
const fs = require("fs");
const LZString = require("lz-string");

const inputPath = process.argv[2] || "file1.rmmzsave";
const outputPath = process.argv[3] || "file1.decoded.json";

const compressed = fs.readFileSync(inputPath, "utf8");
const jsonText = LZString.decompressFromBase64(compressed);

if (!jsonText) {
  throw new Error("Failed to decompress save file. Is this a valid RPG Maker MZ save?");
}

fs.writeFileSync(outputPath, jsonText, "utf8");

console.log(`Decoded save written to: ${outputPath}`);
````

Run:

```bash
node decode-mz-save.js file1.rmmzsave file1.decoded.json
```

---

# 5.4 Editing Common Values

## Example: Editing Gold

Gold is usually stored in party data.

Conceptually, you may find something like:

```json
"_gold": 1234
```

Change it to:

```json
"_gold": 999999
```

---

## Example: Editing Items

Items may be stored by database ID.

Conceptually:

```json
"_items": {
  "1": 5,
  "2": 10
}
```

This means:

```text
Item ID 1: quantity 5
Item ID 2: quantity 10
```

You can modify:

```json
"_items": {
  "1": 99,
  "2": 10
}
```

---

## Example: Editing Switches

Switches are often stored in an array-like structure.

Conceptually:

```json
"_data": [
  null,
  true,
  false,
  true
]
```

Here:

```text
Switch 1 = true
Switch 2 = false
Switch 3 = true
```

Important detail:

> RPG Maker usually uses database IDs starting from `1`, while index `0` is often unused or `null`.

---

## Example: Editing Variables

Variables may also be stored in an array-like structure.

Example:

```json
"_data": [
  null,
  10,
  25,
  999
]
```

This may mean:

```text
Variable 1 = 10
Variable 2 = 25
Variable 3 = 999
```

---

## Example: Editing Actor Level

Actor data may contain level, experience, HP, MP, and equipment.

Possible fields:

```json
"_level": 25,
"_exp": {
  "1": 12345
},
"_hp": 500,
"_mp": 120
```

Be careful when editing levels directly. RPG Maker often derives level from experience. If you only edit `_level`, the game may later recalculate it from `_exp`.

A safer approach is usually to edit experience as well.

# 5.5 Re-Encoding the Save File

After editing the decoded JSON, compress it again.

Create:

```text
encode-mz-save.js
```

````javascript
const fs = require("fs");
const LZString = require("lz-string");

const inputPath = process.argv[2] || "file1.decoded.json";
const outputPath = process.argv[3] || "file1.rmmzsave";

const jsonText = fs.readFileSync(inputPath, "utf8");
const compressed = LZString.compressToBase64(jsonText);

fs.writeFileSync(outputPath, compressed, "utf8");

console.log(`Encoded save written to: ${outputPath}`);
````

Run:

```bash
node encode-mz-save.js file1.decoded.json file1_modified.rmmzsave
```

Then replace the original save:

```bash
cp file1.rmmzsave file1_backup.rmmzsave
cp file1_modified.rmmzsave file1.rmmzsave
```

---

# 5.6 Combined Decode/Edit/Re-Encode Workflow

Recommended workflow:

```text
1. Back up original save
2. Decode `.rmmzsave` to JSON
3. Pretty-print JSON
4. Edit carefully
5. Validate JSON syntax
6. Re-compress to Base64 with LZString
7. Replace original save file
8. Start game and test
```

---

## Example Complete Workflow

```bash
mkdir save_edit
cd save_edit

cp /path/to/game/save/file1.rmmzsave ./file1_original.rmmzsave
cp file1_original.rmmzsave file1_working.rmmzsave

npm init -y
npm install lz-string

node decode-mz-save.js file1_working.rmmzsave file1.decoded.json
```

Edit:

```text
file1.decoded.json
```

Then re-encode:

```bash
node encode-mz-save.js file1.decoded.json file1_modified.rmmzsave
```

Install:

```bash
cp file1_modified.rmmzsave /path/to/game/save/file1.rmmzsave
```

# 5.7 Pretty-Printing the Decoded JSON

The decoded JSON may be minified. You can pretty-print it with Node.js:

````javascript
const fs = require("fs");

const inputPath = process.argv[2] || "file1.decoded.json";
const outputPath = process.argv[3] || "file1.pretty.json";

const text = fs.readFileSync(inputPath, "utf8");
const data = JSON.parse(text);

fs.writeFileSync(outputPath, JSON.stringify(data, null, 2), "utf8");

console.log(`Pretty JSON written to: ${outputPath}`);
````

Run:

```bash
node pretty-json.js file1.decoded.json file1.pretty.json
```

# 5.8 Editing Through the Game Runtime

Sometimes the safest way is not to edit the raw save file, but to modify data through the game runtime and then save normally.

For example, in developer console:

```javascript
$gameParty.gainGold(999999);
DataManager.saveGame(1);
```

Or set a switch:

```javascript
$gameSwitches.setValue(10, true);
DataManager.saveGame(1);
```

Or set a variable:

```javascript
$gameVariables.setValue(5, 100);
DataManager.saveGame(1);
```

This approach is safer because RPG Maker handles object consistency itself.

# 6. Common Errors and Troubleshooting

## 6.1 Wrong File Extension

### Symptom

You try to decode a `.rmmzdata` file and decompression fails.

### Cause

`.rmmzdata` may not be a standard save file. RPG Maker MZ save files are usually:

```text
.rmmzsave
```

### Fix

Check the actual save directory:

```text
<GameDirectory>/save/
```

Look for:

```text
file1.rmmzsave
global.rmmzsave
config.rmmzsave
```

---

## 6.2 `decompressFromBase64` Returns `null`

### Symptom

Node.js script outputs:

```text
Failed to decompress save file
```

### Possible Causes

- File is not an RPG Maker MZ save file
- File is encrypted or modified by a plugin
- File is corrupted
- Wrong compression method used
- File was copied incorrectly
- You are trying to decode a browser localStorage entry incorrectly

### Fixes

- Verify file extension is `.rmmzsave`
- Try another save slot
- Check whether the game uses custom save plugins
- Ensure the file is read as UTF-8 text
- Confirm the file content looks like Base64 text

---

## 6.3 JSON Parse Error

### Symptom

After decompression:

```text
SyntaxError: Unexpected token ...
```

### Possible Causes

- Decompressed output is incomplete
- File was not correctly decompressed
- The save uses custom serialization
- The JSON was manually edited and broken

### Fixes

- Decode again from the original backup
- Use a JSON validator
- Avoid editing structural fields
- Edit only simple numeric or boolean values first

---

## 6.4 Game Says Save Is Corrupted

### Symptom

The game refuses to load the modified save.

### Possible Causes

- Invalid JSON structure
- Missing required fields
- Wrong compression method
- Plugin integrity check
- Game version mismatch
- Edited data violates game logic
- Changed actor/item IDs to nonexistent IDs

### Fixes

- Restore backup
- Make smaller edits
- Do not remove fields
- Do not rename object keys
- Check database IDs in `data/Items.json`, `data/Actors.json`, etc.
- Ensure the save is compressed with `LZString.compressToBase64`

---

## 6.5 Save Loads but Game Crashes Later

### Symptom

The save loads, but the game crashes after opening menu, entering battle, or changing maps.

### Possible Causes

- Actor equipment references invalid weapon/armor IDs
- Party contains invalid actor IDs
- Current map ID does not exist
- Player coordinates are outside map boundaries
- Quest state is inconsistent
- Plugin data was partially modified

### Fixes

- Compare with a valid save
- Avoid editing map/player fields unless necessary
- Verify IDs against database files
- Keep plugin-added sections unchanged
- Modify values through runtime console when possible

---

## 6.6 Editing Level Does Not Work

### Symptom

You change actor level, but the game resets it.

### Cause

Actor level may be derived from experience.

### Fix

Edit experience instead of only level, or use runtime functions:

```javascript
$gameActors.actor(1).changeLevel(50, false);
DataManager.saveGame(1);
```

---

## 6.7 Item Changes Do Not Appear

### Symptom

You edit item counts, but inventory does not update.

### Possible Causes

- Wrong item category edited
- Item ID does not exist
- Item amount exceeds game/plugin limit
- You edited weapons instead of items, or armors instead of weapons

RPG Maker separates:

```text
Items
Weapons
Armors
```

Possible internal containers:

```text
_items
_weapons
_armors
```

### Fix

Check the database files:

```text
data/Items.json
data/Weapons.json
data/Armors.json
```

Then confirm the correct ID.

---

## 6.8 Browser Save Not Found

### Symptom

There is no `save/` folder.

### Cause

The game may be running in browser mode and using localStorage or IndexedDB.

### Fix

Open browser developer tools and check:

```text
Application → Local Storage
```

Look for keys related to the game title or RPG Maker storage.

---

## 6.9 Plugin Compatibility Problems

### Symptom

Decoded save contains unexpected fields or crashes after editing.

### Cause

Plugins can add custom save data.

### Fix

Search plugin files in:

```text
js/plugins/
```

Look for code involving:

```javascript
DataManager.makeSaveContents
DataManager.extractSaveContents
StorageManager
JsonEx
```

These functions reveal custom save structures.

---

# Practical Recommendation

For most save editing tasks, the safest order is:

```text
1. Back up the save.
2. Decode with LZString.
3. Edit only simple values first:
   - Gold
   - Item counts
   - Switches
   - Variables
4. Re-encode with LZString.
5. Test in game.
6. Avoid editing complex object structures unless you understand the game database and plugins.
```

If you have access to the in-game developer console, runtime editing is often safer:

```javascript
$gameParty.gainGold(999999);
$gameSwitches.setValue(10, true);
$gameVariables.setValue(5, 100);
DataManager.saveGame(1);
```

This allows RPG Maker MZ to maintain internal object consistency instead of relying on manual JSON editing.
